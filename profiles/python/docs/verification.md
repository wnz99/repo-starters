# Acceptance checklist

Execute these checks in disposable copies after the final changes. For Python mutation probes, disable bytecode writes and remove the disposable fixture's existing bytecode caches after mutation/restoration; same-size edits within a filesystem timestamp interval can otherwise reuse stale bytecode. Do not delete caches in the user's checkout. Record command, expected outcome, actual exit status, and relevant diagnostic in a verification section of `docs/development.md`. An acceptance result is `pass`, `fail`, or `not-run` with a reason. A failed or unrun required gate prevents a complete-bootstrap claim.

| Contract             | Required probe                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Coolify deployment | For an explicitly selected Coolify deployment, run [deployment acceptance](coolify.md#verification-and-rollback). Pending selection leaves adaptation pending without blocking local quality setup. |
| Full tool wiring     | Frozen installs followed by every applicable root/component check, tests, and real builds. Record exact tool versions; fail on missing tools or no tests collected.                                                                                                                                                                                                                                                                                  |
| Python root policy   | In every component, add a temporary local Ruff block selecting only `F`, and a source `print` call. Native lint must still fail with root `T201`. Add local weakening Pylint/pytest configuration and demonstrate the explicit root files still govern their checks.                                                                                                                                                                                 |
| Read-only lint       | Enable `fix=true` in a disposable inherited Ruff config, add an unused import, and invoke the native lint task. Require nonzero/F401 and byte-identical source; restore and rerun the passing check.                                                                                                                                                                                                                                                 |
| Type coverage        | Inventory maintained source/tests/scripts and compare with resolved Ruff/BasedPyright/tsc/ESLint coverage. Put a deliberate type error and lint violation in a representative file of each category and require the relevant native command to fail.                                                                                                                                                                                                 |
| Real tests           | Introduce a wrong expected result in an actual behavior test, require failure, restore, and require success. Test-runner or collection failure is not proof of assertion detection.                                                                                                                                                                                                                                                                  |
| Python isolation     | Build the component and its declared internal dependency closure as wheels. Export locked external requirements with `uv export --frozen --package <name> --no-dev --no-emit-workspace`; install them plus the built wheels in a fresh environment outside the workspace. Install the component's declared test dependencies there and run copied tests, with no sibling source paths/PYTHONPATH or root tooling site-packages. No editable install. |
| TypeScript isolation | Pack the component and its declared internal dependency closure. Install the packed artifacts and only declared test dependencies outside the workspace using the same registry/lock resolution policy. Run consumer import/startup and tests without root node_modules. Browser artifacts additionally require a browser runtime smoke test.                                                                                                        |
| Local-state hygiene  | A dummy ignored root `.agent-local.json` is allowed. Force-tracking it makes the hygiene gate fail. Also force-track a dummy ignored `.env` and require failure without reading its content. Verify Git index/ignore state without reading credentials. A selected secret-free project MCP registration is allowed and is not this local-only fixture. Restore the fixture index.                                                                    |
| Nx selection         | Mutate component source, each ecosystem lockfile, root language policy, a shared bootstrap/Nx file, and rename/delete a source. Check the selected project set against the known dependency graph. Invalid/missing base and failed discovery must fail or take the documented no-base full-check path.                                                                                                                                               |
| Nx cache             | Warm a static target, confirm its second run hits cache, then mutate its shared policy and declared dependency input separately; both must miss cache and reevaluate. Tests and integrations must execute on both runs.                                                                                                                                                                                                                              |
| Optional states      | Included integrations perform their smoke checks. Excluded ones create no settings. Pending ones stay pending without settings; unavailable included ones report incomplete. Verify the selected client/scope rather than guessing a config path.                                                                                                                                                                                                    |
| Repeat execution     | Reapply with identical baseline, inputs, lockfiles, and skill revisions. No configuration changes, duplicate registrations/hooks/skills, unrelated file changes, or branch switches. Detect and preserve a deliberately edited generated file rather than overwrite it.                                                                                                                                                                              |
| OKF                  | Parse all concept metadata with a YAML parser, require non-empty string type/title/description, validate navigation entries and local links, and keep `index.md` free of frontmatter.                                                                                                                                                                                                                                                                |

Exceptions are entries in `docs/development.md` with path/tool/rule, concrete reason, user decision when the contract changes, removal condition for temporary holds, and verification impact. Do not introduce a second exclusion source or silently enlarge ignores to pass the probes.

The supplied CI runs full checks. Nx affected-selection probes become required before enabling affected CI for the adapted graph. Browser, Node application, additional operating-system, integration and client probes apply only to declared targets. Record other rows as not applicable with a concrete reason when the ecosystem or feature is absent. Starter-release evidence does not certify a newly adapted application.
